# ИИ-автоответчик для FunPay Cardinal

Плагин [Cardinal](https://github.com/sidor0912/FunPayCardinal), который отвечает покупателям
в чатах FunPay с помощью любой ИИ-модели через OpenAI-совместимый API. Продавец спит - бот
консультирует за него: отвечает на частые вопросы по заранее заготовленным прайсу и FAQ,
а если ИИ недоступен - вежливо просит подождать.

Подходит любой OpenAI-совместимый шлюз: OpenAI, OpenRouter, DeepSeek, Groq, vLLM,
LLM Proxy и т.д. - всё, что умеет `POST /chat/completions`.

## Что внутри

- Ответ покупателю собирается из трёх частей: **персона** (стиль общения) + **прайс и FAQ**
  (ваши цены и условия) + текст сообщения покупателя.
- **Fallback**: если LLM не ответил (ошибка сети, 500, пустой ответ) - покупателю уходит
  статичный запасной текст, ошибка пишется в лог.
- **Кулдаун на чат** (по умолчанию 60 секунд) - бот не спамит, даже если покупатель пишет
  подряд.
- **Защита от цикла**: бот не отвечает на свои же сообщения, сообщения авто-выдачи,
  FunPay Vertex, поддержки и системные уведомления FunPay.
- Ответы на системные сообщения (заказы, отзывы) не отправляются - только живые сообщения
  покупателей.
- Сетевой запрос выполняется в фоновом потоке - основной цикл Cardinal не блокируется.

## Установка

### Способ 1: через Telegram-бот Cardinal
1. Откройте бота Cardinal, `/menu` -> «Плагины» -> «Добавить плагин».
2. Перешлите файл `ai_responder.py`.
3. Перезапустите Cardinal (или плагин подхватится сразу).

### Способ 2: файлом
1. Скопируйте `ai_responder.py` в папку `plugins/` рядом с Cardinal.
2. Перезапустите Cardinal.

При первом запуске плагин сам создаст:
- `storage/plugins/ai_responder_config.json` - конфиг;
- `storage/plugins/ai_responder_persona.txt` - персона (стиль ответов, можно править).

## Настройка

Откройте `storage/plugins/ai_responder_config.json`:

```json
{
  "enabled": false,
  "cooldown": 60,
  "request_timeout": 30,
  "retries": 1,
  "llm": {
    "base_url": "https://api.openai.com/v1",
    "api_key": "",
    "model": "gpt-4o-mini",
    "temperature": 0.4,
    "max_tokens": 300
  },
  "fallback_text": "Здравствуйте! Продавец сейчас не в сети, но ответит вам в ближайшее время...",
  "price": "",
  "faq": ""
}
```

| Ключ | Что это |
|---|---|
| `enabled` | вкл/выкл (управляется также командами `/ar_on`, `/ar_off`) |
| `cooldown` | кулдаун на чат в секундах (по умолчанию 60) |
| `request_timeout` | таймаут запроса к LLM в секундах (30) |
| `retries` | число повторов при ошибке (1 повтор = 2 попытки всего) |
| `llm.base_url` | адрес шлюза, например `https://openrouter.ai/api/v1` |
| `llm.api_key` | **ваш ключ** - вписывается только сюда, локально |
| `llm.model` | имя модели, например `openai/gpt-4o-mini`, `deepseek-chat` |
| `llm.temperature` | креативность (0.4 - почти фактические ответы) |
| `llm.max_tokens` | лимит длины ответа (300 - примерно 2-4 предложения) |
| `fallback_text` | запасной текст, когда LLM недоступен |
| `price` | ваш прайс-лист (подставляется в промпт) |
| `faq` | ваши частые вопросы и ответы (подставляется в промпт) |

Пример заполнения `price` и `faq`:

```json
"price": "Аккаунт Steam с играми - 300 руб.\nКлюч игры X - 150 руб.\nСрок выдачи - до 5 минут после оплаты.",
"faq": "В: Есть гарантия?\nО: Да, 30 дней с момента покупки.\nВ: Можно дешевле?\nО: Цена фиксированная."
```

Персону (стиль общения) можно менять в файле
`storage/plugins/ai_responder_persona.txt` - изменения подхватываются без перезапуска.
Исходник дефолтной персоны лежит также в `prompts/default_persona.txt` в комплекте.

### Подключение своего шлюза

Любой OpenAI-совместимый endpoint:

- OpenAI: `base_url = https://api.openai.com/v1`, `model = gpt-4o-mini`
- OpenRouter: `base_url = https://openrouter.ai/api/v1`, `model = openai/gpt-4o-mini`
- DeepSeek: `base_url = https://api.deepseek.com/v1`, `model = deepseek-chat`
- Свой локальный шлюз (например vLLM): `base_url = http://localhost:8000/v1`,
  `api_key` можно оставить пустым

## Команды Telegram

| Команда | Действие |
|---|---|
| `/ar_on` | включить автоответчик |
| `/ar_off` | выключить автоответчик |
| `/ar_test` | тестовый прогон: бот спросит модель и покажет её ответ (или fallback). Можно так: `/ar_test сколько стоит?` |

## Безопасность

- **golden_key и данные аккаунта никуда не отправляются.** Плагин не читает их для
  сетевых запросов и не логирует.
- Единственный сетевой адрес, куда плагин отправляет данные - **явно указанный вами
  `llm.base_url`**. Туда уходят только: персона, прайс, FAQ и текст сообщения покупателя.
- `api_key` хранится только локально в `storage/plugins/ai_responder_config.json`
  и передаётся исключительно в заголовке запроса к вашему шлюзу.
- Никакой телеметрии, аналитики и «домашних» серверов. Код открытый - можно проверить.

## Поведение при ошибках

- LLM недоступен / ошибка / пустой ответ -> покупателю уходит `fallback_text`,
  в лог пишется предупреждение.
- Конфиг не заполнен (пустой `api_key` при дефолтном `base_url`) -> бот молчит,
  ничего покупателям не шлёт (защита от спама заглушкой на неотлаженной установке).
- Пустой `base_url` -> запрос не выполняется, в лог предупреждение.

## Тесты

```bash
pip install pytest requests
pytest tests/test_fallback.py -v
```

Проверяются: fallback при HTTP 500 / битом ответе / недоступном endpoint, кулдаун на чат,
игнорирование сообщений владельца и бота, сборка промпта, сохранение и перечитывание
конфига, обязательные атрибуты плагина. Тестам не нужен установленный Cardinal.

## Совместимость

- Cardinal (Python 3.11+), новый режим получения сообщений (по умолчанию).
- Зависимости: только `requests` (уже есть в Cardinal). Ничего дополнительного ставить не нужно.
- Windows / Linux / Docker - без разницы.

## Ограничения

- Ответ строится по одному сообщению (без истории переписки) - так дешевле и безопаснее.
- В старом режиме получения сообщений (`oldMsgGetMode`) плагин не срабатывает - используйте
  новый режим (он включён по умолчанию).

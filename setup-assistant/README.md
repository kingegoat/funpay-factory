# Настройка Cardinal с ассистентом - Telegram-бот

Продукт линейки «Cardinal-фабрика». Бот-проводник по установке
[FunPayCardinal](https://github.com/sidor0912/FunPayCardinal): ведёт продавца
FunPay по шагам (Windows или Docker), ловит сбои веткой траблшутинга и
заканчивает чеклистом с мягким предложением плагинов.

Покупатель всё делает сам на своей машине: бот ничего не устанавливает,
не подключается к компьютеру покупателя и не имеет удалённого доступа.

## Как работает сценарий

- `/start` - приветствие и выбор платформы: Windows или Docker.
- Каждый шаг - экран с командами и кнопками:
  **Получилось** / **Не получилось** / **Пропустить** / **Позвать человека**.
- «Не получилось» открывает ветку траблшутинга текущего шага: 3-5 частых
  причин, по кнопке - причина и решение, затем возврат в поток
  («Решилось - дальше» или «Вернуться к шагу»).
- «Позвать человека» - контакт поддержки и напоминание не пересылать
  golden_key и токены.
- Финал - чеклист проверки и мягкий апселл плагинов «Монитор позиций» и
  «ИИ-автоответчик» (без давления: «это необязательно, базовый Cardinal уже
  работает»).
- Пропущенные шаги отмечаются в чеклисте - прохождение можно пройти заново
  кнопкой или командой `/start`.

Ветка Windows: Python 3.11 - загрузка репозитория - `Setup.bat` -
golden_key - бот у @BotFather - мастер настройки (`Start.bat`) - проверка -
24/7. Ветка Docker: установка Docker - клонирование - `docker compose build` -
golden_key - бот у @BotFather - `docker compose run --rm funpaycardinal` -
`up -d` - 24/7. Шаги сверены с официальным README FunPayCardinal
(Setup.bat, Start.bat, configs/_main.cfg, команда `docker compose run --rm
funpaycardinal`).

## Требования

- Python 3.11+
- Токен Telegram-бота

## Быстрый старт

1. Создайте **нового** бота у [@BotFather](https://t.me/BotFather):
   `/newbot`, имя, username (оканчивается на `bot`), скопируйте токен.
   Не переиспользуйте токены старых ботов.
2. `cp .env.example .env` и заполните `BOT_TOKEN`, при желании
   `SUPPORT_USERNAME` (ник поддержки для кнопки «Позвать человека», без `@`).
3. Установите зависимости и запустите:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python bot.py
```

В логах появится `Бот @username запущен` - можно писать ему `/start`.

## Запуск на сервере

### systemd

Инструкции - в шапке `deploy/setup-assistant.service`
(пути `/opt/setup-assistant`, пользователь `setupbot`, `Restart=on-failure`).
Логи: `journalctl -u setup-assistant -f`.

### Docker

```bash
cp .env.example .env   # заполнить BOT_TOKEN
docker compose -f deploy/docker-compose.yml up -d --build
docker compose -f deploy/docker-compose.yml logs -f
```

## Конфигурация (.env)

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен нового бота от @BotFather |
| `SUPPORT_USERNAME` | нет | Ник поддержки для «Позвать человека»; пусто - бот отошлёт к продавцу ассистента |
| `LOG_LEVEL` | нет | Уровень логов, по умолчанию `INFO` |

## Надёжность и безопасность

- **Никаких данных аккаунтов.** Бот не запрашивает и не пересылает golden_key,
  токены и что-либо с машины покупателя: все секреты покупатель вводит сам
  в консоли Cardinal. Это же написано в текстах бота.
- **Никакой телеметрии.** Внешние соединения - только с Telegram API.
- Состояния FSM - `MemoryStorage`: хранятся в оперативной памяти и после
  перезапуска сбрасываются (покупатель просто жмёт `/start`).
- Анти-флуд: не более 5 апдейтов от пользователя за 3 секунды, лишнее
  отбрасывается.
- Любое необработанное исключение перехватывается глобальным обработчиком:
  лог с трейсбеком, пользователю - извинение и `/start`, бот продолжает работу.
- Логи содержат только id пользователей и события сценария.

## Кастомизация

Весь контент - в `steps.py`: тексты шагов, частые причины, чеклист и апселл.
Формат простой (dataclass `Step` с полями `title`, `body`, `tip`, `causes`),
правится без знания aiogram. Разрешённые теги HTML: `<b> <i> <u> <code> <pre>`.
После правки перезапустите бота.

Проверить контент после правок можно тестами:

```bash
python3 tests/test_steps.py        # только стандартная библиотека
.venv/bin/python tests/smoke_import.py   # импорт бота, рендер всех экранов

# полный набор (нужны pytest и pytest-asyncio):
.venv/bin/pip install pytest pytest-asyncio
.venv/bin/python -m pytest tests/
```

Что ловят тесты: пустые поля контента, число причин вне диапазона 3-5,
дубликаты id, запрещённые HTML-теги, «голые» амперсанды и длинные тире;
всю ветку сценария (выбор ОС, шаги, траблшутинг, «Позвать человека»,
финал с апселлом, рестарт), устаревшие кнопки, анти-флуд и подсказки
на свободный текст - всё без обращения к сети Telegram.

## Структура проекта

```
setup-assistant/
├── bot.py                     # логика бота (aiogram 3.x, FSM, throttle)
├── steps.py                   # контент: шаги Windows/Docker, траблшутинг, чеклист
├── tests/
│   ├── test_steps.py          # целостность контента (stdlib)
│   ├── test_flow.py           # интеграционные тесты сценария (aiogram)
│   └── smoke_import.py        # импорт и рендер всех экранов
├── requirements.txt           # aiogram, python-dotenv
├── .env.example               # шаблон конфигурации (токен НЕ вшит)
└── deploy/
    ├── Dockerfile
    ├── docker-compose.yml
    └── setup-assistant.service
```
